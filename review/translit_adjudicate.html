Transliteration adjudication

What each tab is asking

Witnesses (decide first)

Rows whose recorded transliteration carries a faulty token. Because the composer learns its lexicon from completed rows, one of these can be the sole witness for a losing reading — correcting it dissolves a contest downstream rather than requiring a separate ruling on it. One row may hold several fixes, so the card is keyed by fix, not by row.

Homographs

13 rows that apply_word_lexicon.py refuses to compose: one normalized Arabic key carries two attested readings, so composing would mean guessing. Pick the reading this row's context requires.

Normalizer artifact
normalize_ar folds ألف مقصورة (ى) to yāʾ (ي) — correct for matching names, but it merges على ʿalā with علي ʿAlī onto one key. The raw title tells you which it is.
Genuine homograph
One spelling, two words: من is the preposition min and the relative pronoun man.
Witness rows
Rows whose existing transliteration attests that reading. One witness against several is usually a typo, not a distinction.

Orthography

Arabic word forms that look non-standard, with a proposed canonical spelling. Up to two answers: the Arabic form, and — where the word appears in a title — the transliteration that form implies, because changing the Arabic changes the lexicon key the composer looks it up under, so a spelling fix with no transliteration would silently un-settle the word. A word that appears only in author fields and cluster names has no per-word romanization, so that second question is not asked there: the Arabic form is the whole decision.

Where the corpus records more than one reading for the same word, no default is offered and the competing readings appear as one-click choices. The disagreement is itself a finding — pick one, or type a third.

clear
A real fault: the spelling is wrong by any convention.
check
Probably a fault, but worth a look at the manuscript reading.
house-style
Not wrong — inconsistent. The corpus writes it both ways (or drops an optional hamza). Your call is a convention, and «keep as written» is a legitimate answer.
shadda
The transliteration geminates, so the Arabic should carry a šaddah. The placement was derived from the transliteration's doubled consonant and is offered for one-click acceptance.
shadda-manual
Same, but WHICH letter carries the mark is not mechanically decidable — the consonant occurs more than once outside the article, or the transliteration doubles two of them. No proposal is offered; type the form.

What the šaddah does and does not do

It does not affect matching. normalize_ar strips every combining mark, so القدسيّة and القدسيه are ONE lexicon key — writing the mark changes no key and unblocks no title. What it buys is the reverse check: with the mark present, a scan can verify a transliteration's doubling against the Arabic, which is how the witness-tab faults were found. The corpus currently writes it on 16 word types and omits it on the rest; nothing carries a šaddah the transliteration contradicts, so the rule holds in one direction already.

Where the transliteration is the thing that is wrong (a doubled consonant the Arabic never had), the fix is a Witnesses card, not a šaddah — those words are held out of this tab deliberately.

Attribution

Rows whose title ends in a li- attribution naming a person. The default is keep, deliberately: a census of the whole corpus found that titles containing a person-name are overwhelmingly the work's real title (تفسير مقاتل, حكم أبي مدين — strip those and you are left with «تفسير» and «حكم»), and that most of the remaining tails name the author of the base text a commentary is about, which the row's own author field does not record.

Each card carries a computed collision check: which other rows in this batch would end up with an identical title if their tails were stripped too. On this batch it comes back empty for every card — so "stripping would merge these records" is NOT an argument available here, and the case for keeping rests only on whether the tail is information worth having. One card is flagged a false positive: r0285's للمفتاح is «for the key», not a name.

Stripping never deletes: the tail is appended to catalog_note, and the transliteration is trimmed with it only when the row's two sides have matching word counts.

Hamzat qaṭʿ vs waṣl

A word-initial hamza is either qaṭʿ (written أ or إ, always pronounced) or waṣl (a bare ālif, elided in context). The corpus writes a bare ālif for both, so only the qaṭʿ ones need fixing — "correcting" a waṣl word would be an error.

Which one it is comes from the transliteration, because this project romanizes them identically but the vowel survives: an initial a or u can never be waṣl (that is what separates al-anwār from al-intiṣār), an initial ā is a madda (الآيات, never الأيات), and an initial i is read against the Arabic shape — است / ان / ا_ت and the assimilated form-VIII spellings (اصطلاح, اضطراب) are waṣl and get no card at all.

These fixes are invisible to matching: normalize_ar folds أ إ آ ٱ back to ا, so no cluster key and no lexicon key moves. A card that would move a key says so explicitly — that only happens where a letter, not just a carrier, is being changed.
